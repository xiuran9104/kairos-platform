## 1. 背景

平台已用 Rust + Vben Admin 重建了 Toonflow-app 的主体能力（`crates/modules/toon-server`，约 200+ 条 `/toonflow/**` 路由，28 张 `toonflow` schema 表，前端 8 个页面）。当前目标是把它打磨成一条**完整可用的漫剧工作流**：原著 → 剧本 → 资产 → 分镜 → 图生视频 → 配音 → 合成导出。

优化方向：

- **Toonflow-app**：继续作为功能、流程、字段与交互语义的对齐基准（三层 Agent、文件化 Skill、事件图谱、无限画布）。
- **Jellyfish**：借鉴其工业化流水线能力——分镜状态机、一致性工程（全局种子/风格继承/双层资产库）、关键帧多版本、统一异步任务系统、时间线剪辑。

## 2. 参照对象要点

### 2.1 Toonflow-app（对齐基准）

- 工作流闭环：策划 → 编剧 → 分镜 → 出片；小说章节事件提取构成事件图谱，供改编精确调用上下文。
- 三层 Agent：决策层（decision skill）→ 执行子 Agent（骨架/改编/剧本、衍生资产/生图/导演计划/分镜面板/分镜图）→ 监督层（supervision）。
- 文件化 Skill 体系：11 种画风（2D/3D/真人系）、12 种题材、production 技法、按视频模型/模式分的提示词模板（Seedance 2.0 多参、Wan 2.6 单图首帧、通用首尾帧/多参）。已通过 `script/sync-toonflow-content.mjs` 同步入库。
- 分镜面板条目 12 字段 videoDesc：画面/场景/资产/时长/景别/运镜/动作/情绪/光影/台词/音效/资产ID。

### 2.2 Jellyfish（借鉴来源）

- 官方六步流水线：剧本输入 → 智能分镜 → 一致性管理 → AI 视频生成 → 后期剪辑 → 一键导出。
- **分镜双状态语义**：`shot.status`（信息提取确认 pending/ready）与"视频生成准备度"严格分离；"分镜编辑页 = 准备、分镜工作室 = 生成"职责边界。
- **一致性工程**：全局种子（Global Seed）+ 风格强制继承 + 项目/全局双层资产库，治"角色变脸/场景跳变"。
- **分镜精细控制**：景别/角度/运镜/情绪/时长/氛围/对白/配乐/音效；首帧/尾帧/关键帧独立提示词；多版本管理；参考图跨分镜引用；ControlNet 骨骼/深度；智能对口型（Lip Sync）。
- **统一异步任务系统**：所有生成任务统一状态/取消/恢复。
- **后期**：时间线多轨剪辑、素材库拖拽、最终导出；节点式可视化 Agent 编排。

### 3.2 已知缺口与技术债

- 分镜流程未完成真实数据端到端验证（见 storyboard-sync-plan P0）。
- 前端全量 typecheck 有既有错误（`AgentChat.vue`、`detail.vue`）。
- `/toonflow/assets` 页面存在但路由未注册（孤儿页面）；「Agent 工作台」Tab 为 `v-if="false"` 死代码。
- 同一批 handler 挂在 `/toonflow/x`、`/api/x`、裸 `/x` 三套前缀（Toonflow-app 兼容层）。
- 旧 `/toon/*` 脚手架（`projects.rs/episodes.rs/scenes.rs` + `toon` schema 4 张表 + `toon-api` 全部 DTO）前端零调用，纯遗留。
- 200+ 条 toonflow 路由不在 OpenAPI 文档中（`openapi.rs` 只写了 `/toon/*`）。
- 鉴权粒度粗：几乎所有写操作仅校验 `toon:project:update` 等少数权限码；图片代理公开、WS 手动校验 query token；无租户/属主过滤。
- 主键用时间戳 + offset，高并发下脆弱。
- 测试薄：1 个 `#[ignore]` 集成测试 + 2 个前端小单测。
- 内容（Skill/手册/提示词模板）依赖外部 Toonflow-app 仓库同步，非自包含。

## 6. 非功能需求

- **可靠性**：批量生成并发受控；异步任务可取消/重试；失败原因结构化落库并前端可见。
- **一致性**：同一项目内角色/场景视觉一致（全局种子 + 风格继承 + 参考图链路）。
- **可观测**：Agent 运行、生成任务全链路 tracing；导出等长任务进度可见。
- **部署**：ffmpeg 依赖文档化并在健康检查中探测；MinIO 配置校验前置。
- **安全**：密钥/令牌不落日志；公开接口最小化（当前仅图片代理与 WS）。

## 7. 优先级规划

- **P0 闭环收尾**：分镜流程真实数据端到端验证、typecheck 修复、后端集成测试、回归清单（沿用 storyboard-sync-plan P0）。
- **P1 工作流打磨**：分镜双状态机、全局种子与风格继承、全局资产库、Track 分组 UI、图片编辑流回写、合成预览下载、统一任务系统、权限细化、路由收敛、孤儿页面与死代码处理、16:9 默认画比、旧脚手架删除（决策 1/2/3）。实施拆解见[漫剧工作流实施任务书](./漫剧工作流实施任务书.md)。
- **P2 工业化增强**：关键帧独立提示词、多版本管理、参考图跨分镜引用、Lip Sync、ControlNet、时间线剪辑、Agent 可视化编排、剧本一致性检查、主键策略替换。
- **P2 体验收尾**：响应式与无障碍（沿用 storyboard-sync-plan P2）。

## 8. 验收标准

沿用 parity-roadmap 完成标准：每个条目同时具备 Rust 接口、数据库迁移、权限、前端入口，并通过后端检查、前端类型检查和关键流程测试，才可标记完成。漫剧工作流整体验收 = 用一个测试项目从导入小说到导出成片全链路无人工干预断点走通。

## 9. 决策记录（2026-07-28 已确认）

1. **定位**：横屏 16:9 漫剧为主；`projects.video_ratio` 默认 `16:9`，工作台 UI 横屏优先，其余画比仅保留配置能力。
2. **Jellyfish 借鉴深度**：P1 纳入分镜双状态机、全局种子、风格强制继承；时间线剪辑、Lip Sync、ControlNet 留 P2。
3. **旧脚手架**：确认删除 `/toon/*` 遗留代码、`toon` schema 与 `toon-api` DTO，随 P1 工程治理执行。
4. **供应商模式**：维持 ai-server 统一模型接入，不做 Toonflow 式可编程供应商沙箱。
5. **工作台形态**：保持单页工作台（单台）；分镜"准备/生成"双状态在页内分区呈现，不拆路由。

P0/P1 的实施拆解见[漫剧工作流实施任务书](./漫剧工作流实施任务书.md)。
